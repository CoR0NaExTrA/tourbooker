# Реализация полнотекстового поиска и фильтрации туров

## Статус
Принято (Accepted)

## Контекст
Туристы должны иметь возможность искать туры по множеству параметров: страна, даты, тип отдыха, цена, рейтинг, наличие мест. Поиск должен работать быстро и поддерживать неточный ввод.

## Ограничения
1. **Время отклика:** Поиск и выдача результатов должны занимать не более 200 мс.
2. **Мультиязычность:** Поддержка поиска на разных языках с учетом морфологии.
3. **Агрегации:** Необходимость быстрого подсчета количества туров по категориям.
4. **Нагрузка на основную БД:** Запросы поиска не должны замедлять основную БД, где идут транзакции бронирования.

## Решение
Использовать **Elasticsearch** (или OpenSearch) в качестве поискового движка. Данные из PostgreSQL будут синхронизироваться в Elasticsearch асинхронно.

## Последствия
- **Плюсы:** Молниеносный поиск, встроенный фасетный поиск, поддержка нечеткого поиска и синонимов.
- **Минусы:** Появляется необходимость поддержки синхронизации данных между PostgreSQL и Elasticsearch; Elasticsearch потребляет много оперативной памяти.
- **Риски:** Рассинхронизация данных — турист может увидеть в поиске тур, который только что был забронирован.
